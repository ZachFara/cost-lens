# 0004. Engine types stay out of the repository; the claude CLI is pinned

Date: 2026-11-07. Status: accepted.

## Context

The mod imports types from `claude-code`, an ambient module the engine writes as a `.d.ts` beside a mod it loads in an interactive session (`.claude-plugin/types/claude-code/index.d.ts`). No command writes it otherwise, and it cannot be extracted from the CLI binary. The file is generated by Anthropic's software, and Anthropic's own mod-sharing guide leaves it out of shared repositories. The repository is public. The mod API is early access and changes between releases; `claude plugin validate` and `claude plugin test` check the mod against a specific engine build.

## Decision

- Do not commit the engine's types. `vendor/` is gitignored. `npm run engine-types` copies the engine-written file into `vendor/claude-code/index.d.ts` and refuses a file whose header names a Claude Code version other than the pinned one.
- Pin `@anthropic-ai/claude-code` exactly as a dev dependency, so `npm run check` uses the same engine everywhere.
- `npm run check` is the same command locally and in CI. Locally, a missing types file fails both the type check and ESLint, so every commit is fully checked by the pre-commit hook. In CI (`CI=true`), where the file cannot exist, the mod's type check and the lint of engine-API code (`hooks/`, `src/mod/`, `tests/mod/`) are skipped with a notice; formatting, Node type checks, dead code, boundaries, layout, `claude plugin validate` and every test still run.
- Ship our own `tsconfig.json` so the engine does not write one.

## Consequences

- The public repository holds only our own code.
- CI is weaker than the local check for engine-API code: a commit made with the hook bypassed could pass CI with a mod type error. AGENTS.md forbids bypassing the hook.
- A fresh machine needs one interactive session (`claude --plugin-dir .`) before `npm run engine-types` can copy the file.
- Upgrading Claude Code is one deliberate change: bump the pin, open a session so the engine rewrites the types, `npm run engine-types`, fix what breaks.
